# Benchmark corpus provenance

Two kinds of input feed the benchmark. The files in this directory are generated by `bench/corpus/generate.ts` from standard
command-line tools (ImageMagick `convert`, ffmpeg with its bundled `flite` voice and `aevalsrc`/`mandelbrot` sources, and jszip), from
libraries (pyarrow, openpyxl, fontTools, through `generate-assets.py`), from calibre's `ebook-convert` and from text written for this
project; no third-party photographs, recordings, documents, tables or books are included, so nothing here carries an external licence
except the font outlines (below): all other files are released under the repository licence (CC0 for the generated content). The
public sample sets (photographs, screenshots, video sequences, studio recordings and the Silesia compression corpus) are not in the
repository at all: `remote-manifest.json` pins each file by its origin, size and SHA-256, `bench/corpora.ts` fetches it from the host
that publishes it when a run needs it, and the second half of this file records the licence of every one of them. The public sets of the document, PDF, ebook, font, CAD, RAW, vector and data families work the same way (`public-manifest.json`, `bench/public-samples.ts`) and are recorded in the last section.

`manifest.json` lists the SHA-256 of each generated file; `tests/bench-corpus.test.ts` checks the files against it and the
total against the 5 MB budget. Regenerate with `npx tsx bench/corpus/generate.ts` and commit the new manifest. Most files are a pure
function of the generator; the Parquet, XLSX, font and MOBI files are written by tools that stamp or reorder their output, so the
committed bytes are the record and the manifest pins them (`--only table,book,assets` regenerates just those, which needs
pyarrow, openpyxl, fontTools and calibre, and DejaVu Sans on the machine).

photographs are textures, not natural scenes; they exercise smooth gradients, noise and edges but understate the
detail of real photographs, so absolute numbers are for trend tracking rather than public comparison.

## Public sample sets (fetched at run time, never committed)

`remote-manifest.json` is the record: for every sample the origin (a URL, a byte range of a larger file, or an entry of a ZIP archive
read with range requests), the size and the SHA-256 of the bytes the benchmark measures, and the licence code listed below.
`bench/corpora.ts` fetches a sample into `.bench-corpora/<family>/<sha256>` on first use, and a file whose digest differs from the
manifest fails the run: the benchmark never measures bytes it did not pin. CI restores `.bench-corpora/<family>` with
`actions/cache` keyed by the digest of the manifest (`.github/actions/bench-corpora`), and a run under `ORACLE_STRICT_MODE=1` fails
instead of skipping a sample that cannot be fetched. Re-pin a changed file with `npx tsx bench/corpora.ts pin <seeds.json>`.

None of these files is redistributed by the repository, so the terms below matter for the use the benchmark makes of them: reading
them to measure an encoder, which each set's publisher allows. Where a licence requires attribution, the author is in the manifest
(`meta.author`) and in the row.

Licence rule: only files whose licence allows commercial use are used. Creative Commons NonCommercial (NC) and NoDerivatives (ND) licences are excluded, whatever the use (the files are read for testing and never shown or redistributed); 146 files of the camera sample archive are CC BY-NC-SA and none is used. The standard evaluation sets whose terms allow research and development use (EBU SQAM, the Kodak Photo CD pictures, the NTIA sequences, the Silesia parts without a licence) stay, for internal test use only (QA decision 2026-10-17, `docs/policy-decisions.md` entry 37): they are fetched at run time, never committed, shown, redistributed or shipped, and their rows below say so.

The regression corpus of about 20,000 office and PDF files (`bench/realworld/regression-manifest.json`, QA decision 2026-10-17) is held to the same rule: the government document corpus is published as freely redistributable to the best of the publisher's knowledge, and the web-crawl PDF corpus is under the Common Crawl terms of use and the terms of the digital corpora project, so both are for internal test use only, fetched at run time by digest from the publisher's archives by byte range, never committed, shown, redistributed or shipped, and deleted after each file is judged. Its sources and selection rules are in `bench/realworld/PROVENANCE.md` (Regression corpus).

Notes on how the benchmark uses them. Video sequences are uncompressed 4:2:0 8-bit `.y4m` streams of 5 to 700 MB (the 10-bit and HDR10 sequences of the same
set are not used here: the video rows encode an 8-bit lossless copy, and HDR clips with their colour tags are in the real-world corpus); the manifest pins only
the first frames of each (a byte range, 17 to 75 MB), which is 0.7 to 3 s of video (the 1080p and 720p clips are shorter so that a
pull request stays inside its time). Audio tracks are the stored FLAC entries of the SQAM archive; the benchmark cuts the first 12 s
(6 s for the edge case at 96 kHz) to 16-bit or 24-bit PCM with ffmpeg. Images are used as published; the alpha and 16-bit samples are
declared in the manifest and checked against the decoded file.

## Vector graphics, CAD and office parts

These files are written by `generate-vector-cad.ts` and `generate-office.ts` (CC0, like the rest of the corpus), each
with the ground truth its family scores against. Every shape, entity and number is a pure function of the constants in
the generator, so a re-run yields the same bytes; both generators refresh only their own folders in `manifest.json`.
The camera RAW rows use no committed file: they read the public-domain (CC0) samples of `tests/fixtures/raw/manifest.json`
(`npm run fixtures:raw`), checked against the SHA-256 listed there. The slide rows read
`tests/fixtures/golden/office/drawingml-shapes-presentation.pptx`, checked against `tests/fixtures/golden/corpus-manifest.json`.

## Public samples of the document, PDF, ebook, font, CAD, RAW, vector and data families

The eight families named here (document, PDF, ebook, font, CAD, RAW, vector and data) use the same system as the media and compression
sets above: `remote-manifest.json` pins every sample, `bench/corpora.ts` fetches and caches it, and the licence of each sample is on its
row below. A sample that belongs with companion files (the reference picture of an SVG test, the EPUB whose text is the truth of a
Kindle file) lists them in the manifest, and they are fetched and pinned in the same way. A file is fetched for testing only and is
never redistributed from this repository, so a licence that forbids redistribution would still allow the use; the licences below are
those the publisher states for the file or its repository. The real-world files (`govdocs1` and `poi-test-data`) are the ones the
real-world corpus run already fetches, pinned by the same archive ranges and digests.

How a sample is judged is described in `bench/README.md` (Public sample sets). Licence codes: SPDX identifiers, and
`LicenseRef-Project-Gutenberg` (public domain in the United States, files carry the Project Gutenberg licence text),
`LicenseRef-govdocs1` (documents published by government web servers and distributed by the govdocs1 research corpus as freely
redistributable to the best of the publisher's knowledge), `LicenseRef-US-Government-public-domain` (a US government dataset,
see the `datapackage.json` entry of the dataset) and `LicenseRef-Public-domain-text` (a text in the public domain, in a file made
by a third party).
